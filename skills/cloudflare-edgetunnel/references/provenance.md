# 来源与验收边界

此技能整理于 2026-10-28，依据两段真实操作记录，而不是推测原始部署方式：

- 2026-09-09：edgetunnel 2.1 的 Pages Direct Upload、独立 KV、Production ADMIN secret、重新部署、第三方 DNS 子域名 CNAME、Pages Active/SSL、HTTPS 登录及管理页访问控制。原记录当时明确保留“实际代理连接尚待验收”，不能倒写为当时已完整通过。
- 2026-10-28：在已有实例上修改自定义节点列表、读回订阅验证、生成 VLESS/WS/TLS 行内配置，并完成真实核心代理请求。随后发现 TUN 干扰及 TCP/HTTPS/URL Test 混用，修正为与 Clash 相同内核、URL、unified-delay 的多次测试。

公共部署契约已与 deployment.md 的官方来源核对。技能中的新账号完整部署流程仍需要由每个使用者实际执行验收；本技能包的结构/脚本测试不等于在另一新账号上完成部署。

曾遇到的具体问题被提炼为条件性处理，而非通用要求：邮箱未验证、浏览器缺少本地文件上传权限、变量/KV 修改后未重新部署、外部 DNS 已传播但证书尚未生效、不同名字指向不同节点、公开地区标签和实际机房不一致。

分享包刻意不包含原账号邮箱、项目/域名、账号与资源 ID、ADMIN、UUID、订阅 token、浏览器数据、实际订阅文件和测速临时核心配置。历史 commit 可用于追溯，但不代表当前安全性或持续可用性。
